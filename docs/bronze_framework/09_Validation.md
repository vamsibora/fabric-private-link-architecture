# 09 — Validation

`validation_engine.py` evaluates metadata rules (`control.validation_rule`)
plus built-ins. Every result is written to `audit.validation`.

## Built-in rules

Every entity gets these unless it defines its own rule of the same
`rule_type`.

| Rule | Action | Applies |
|---|---|---|
| `builtin_column_missing` (COLUMN_MISSING) | FAIL | Always (PRE) |
| `builtin_primary_key_null` (PRIMARY_KEY_NULL) | FAIL | Entities with a primary key (PRE) |
| `builtin_duplicate_primary_key` (DUPLICATE_PRIMARY_KEY) | WARN | Entities with a primary key (PRE). Deduplication resolves duplicates; the warning keeps them visible. |
| `builtin_data_type_mismatch` (DATA_TYPE_MISMATCH) | FAIL | Entities with any non-STRING column (PRE). It checks every typed column at once. A column-specific DATA_TYPE_MISMATCH rule adds its own action on top; it does **not** disable this built-in. |

**Why types are checked on raw staging.** Staging is source-shaped. The framework casts it to the
target types once, in `staging_manager.read()`. Spark's default (non-ANSI) `CAST` turns an
unconvertible value into NULL *silently*, so checking the already-cast frame would never catch it.
DATA_TYPE_MISMATCH therefore runs against the raw staging rows of the run
(`staging_manager.read_raw()`). A row fails when the raw source value is NOT NULL but its
conversion is NULL. The conversion is `try_cast`, or the column's `control.column_mapping`
expression. This guards landing JSON (always read as STRING) and copy-typed staging alike.

## Rule types

| rule_type | Evaluation | failed_row_count |
|---|---|---|
| PRIMARY_KEY_NULL | Any PK column NULL | Rows |
| DUPLICATE_PRIMARY_KEY | `GROUP BY pk HAVING COUNT(*) > 1` | Surplus rows |
| MANDATORY_COLUMN_NULL | `column_name IS NULL` | Rows |
| COLUMN_MISSING | Source columns absent from the raw staging table | Columns |
| DATA_TYPE_MISMATCH | On RAW staging: source value not NULL but its conversion (`try_cast(… AS target_data_type)` or the mapping expression) is NULL | Rows |
| WATERMARK_INVALID | Watermark NULL, or older than the stored watermark (incremental) | Rows |
| ROW_COUNT_ANOMALY | `abs(% change of staged rows vs previous successful run) > row_count_anomaly_threshold_pct`. The baseline comes from `audit.usp_get_entity_baseline`. | — (actual = % change) |
| CUSTOM | `NOT (<expression>)` | Rows |

**Stages:** `PRE` runs on the staged batch before any transformation. `POST`
runs on the Bronze table after the write.

**Failure actions:**

| failure_action | Rule fails → status | Effect |
|---|---|---|
| FAIL | FAILED | Blocks the entity when `fail_on_validation_error = true` (`ValidationFailedError`, non-retryable) |
| WARN | WARNING | Recorded; processing continues |
| IGNORE | IGNORED | Recorded; never affects the outcome |

A POST failure leaves the Bronze write committed but does **not** advance the
watermark. The entity is FAILED, and a re-run reprocesses idempotently.

The SQL is generated by pure functions over a temp view
(`build_rule_sql`), so it is unit tested without Spark. Results carry counts
and thresholds only, never row values. `CUSTOM` expressions are trusted
metadata: review them as code, since they execute as Spark SQL.
